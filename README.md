# vps-troubleshooting

一台远程 VPS 变慢、连不上、或者网站登不上时，用测量定位到具体哪一层，再决定改什么。

适用于任何 VPS 和服务商。机房和线路不同，排查方法一样。

## 能做什么

- 判断慢在服务器上行、跨境线路，还是客户端自己的网络
- 判断连不上是服务没起、防火墙没开、DNS 不对，还是路径被封
- 决定该不该开 BBR，以及怎么测才算有效对照
- 判断加 CDN 能改善什么、不能改善什么
- 定位多设备订阅加载失败的原因
- 区分"隧道能连"和"网站能用"

## 使用

把这句话发给 AI：

```
读 https://github.com/<owner>/vps-troubleshooting 里的 skill/vps-troubleshooting/SKILL.md，
按它的流程诊断我这台 VPS，先只做只读检查。
```

不用 AI 的话，直接读 `skill/vps-troubleshooting/references/` 下对应的文件，里面有命令和判断标准。

## 实测案例

一台洛杉矶 VPS，客户端在北京，通过移动网络访问。下面是用本仓库方法测出来的数据。

### 慢在哪一层

| 测量 | 结果 | 说明 |
| --- | --- | --- |
| VPS 到公网下载 | 约 45 MB/s | 服务器上行不是瓶颈 |
| 单流下载 | 14–15 KB/s | 比服务器慢三个数量级 |
| 四条并行合计 | 51.5 KB/s | 容量存在，单流被压制 |
| RTT | 约 195 ms | 长路径，窗口增长慢 |
| 丢包 | 6.7%–20% | 间歇丢包打垮基于丢包的算法 |
| 传输中 cwnd | 1–3 MSS | 窗口塌了 |
| 重传比例 | 约 15.7% | 确认真实丢包，不只是延迟 |

单流和多流的差距是这里的核心证据。四条流合计 51.5 KB/s 而单流只有 15 KB/s，说明链路还有容量，问题出在单条连接的拥塞控制，不在带宽。

### 开 BBR 之后

交替三轮，只对测试连接设算法，全局保持 CUBIC：

| 轮次 | CUBIC | BBR |
| --- | ---: | ---: |
| 1 | 34.0 KB/s | 110.9 KB/s |
| 2 | 29.8 KB/s | 104.2 KB/s |
| 3 | 42.4 KB/s | 108.6 KB/s |
| 中位数 | 34.0 KB/s | 108.6 KB/s |
| 上传（各一次） | 705 KB/s | 719 KB/s |

下载约 3.19 倍，但 108 KB/s 仍然不快。上传没有明显变化，因为服务器的算法管不到客户端的发送方向。

### 加 Cloudflare 入口之后

同一份 4 MiB 数据，交替三轮：

| 路径 | 中位数 |
| --- | ---: |
| 原 Shadowsocks 直连 | 1.075 MB/s |
| 新 VLESS/WS 经 Cloudflare | 1.592 MB/s |
| 同协议直连源站 | 1.347 MB/s |

CF 比原节点高约 48%，比同协议直连高约 18%，三轮区间互相重叠。不能承诺固定倍数，有时也更慢。

普通 HTTPS 对照：下载 0.993 → 1.700 MB/s，上传 543 → 497 KB/s。

### 订阅分发

| 项目 | 数值 |
| --- | --- |
| 原始大小 | 约 2.53 MB，121,344 条规则 |
| gzip 后 | 约 558 KB |
| 拉取耗时 | 约 180 秒 → 约 42 秒 |

gzip 只影响订阅下载，不影响上网速度。

### 这个案例说明的边界

- CF 改变的是入口，出口 IP 仍是那台 VPS，所以不解决网站的风控挑战
- BBR 改善发送侧，不创造容量，也不能修好一条本身没有余量的路径
- 108 KB/s 说明这类机房加这条线路不适合当主力出口，换协议和调参都救不回来

## FAQ

### 开了 BBR 还是慢，为什么

BBR 改善的是发送侧在丢包路径上的表现。如果瓶颈在服务器上行、路径容量、或者高峰拥塞，它没有作用。先测单流和多流：两者接近说明路径没余量，BBR 救不了。

### 单流慢但多流加起来正常，是什么问题

链路有容量，单条连接被丢包惩罚了。查 RTT 和丢包率，再看传输中的 cwnd 和重传比例。这类情况调拥塞控制可能有效。

### 服务在跑，但外部连不上

最常见的原因是主机防火墙开了、服务商安全组没开。两层都要确认，并且从外部用 `nc` 实测端口，不要只看配置文件。

### 加 CDN 能不能解决网站登录问题

不能。CDN 改变客户端到 VPS 的入口，出口 IP 还是那台 VPS，目标网站看到的身份没变。

### 为什么 Shadowsocks 加不了 CDN

CDN 只代理 HTTP 系流量。Shadowsocks 是裸 TCP/UDP，套不上去。要用 CDN 必须在安装前换成 VLESS/WS/TLS 这类传输，装完再改要重装。

### 订阅能拉下来，但客户端节点列表是空的

先确认是下载失败还是解析失败。下载失败是网络，解析失败是内容或兼容问题。也可能是客户端自己的覆写注入了服务器没发的字段，这时要看客户端实际生效的配置。规则集体积过大是可能原因之一，但没有客户端侧证据不能定论。

### 测速结果每次都不一样，怎么判断有没有改善

同一时段交替测对照组和处理组，比如 `C,T,T,C,C,C,T`，报多轮中位数。两组数值区间重叠就说明差异没成立，不能算成百分比提升。

### 能不能直接抄一套 sysctl 参数

不建议。缓冲区大小取决于带宽乘 RTT、内存、并发数和机器角色。1 GB 内存的机器抄 256 MB 缓冲只会变成负担。

### 这个仓库和网上的 VPS 优化脚本有什么区别

脚本通常直接改参数并重启服务。这个仓库先测量再决定改不改，并且要求留下回滚路径。很多"优化"在测量后发现没有必要。
