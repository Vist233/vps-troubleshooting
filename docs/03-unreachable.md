# 3. 连不上：超时或连接被重置

"连不上"至少有六种原因，分布在六层。大部分浪费时间的排查，都是在修一层根本没坏的地方。

## 检查顺序

从便宜、最有决定性的开始。

```
1. 服务在跑吗？              systemctl is-active
2. 监听在对的地方吗？        ss -ltnp
3. 两层防火墙都开了吗？      VPS 防火墙 + 服务商安全组
4. VPS 自己能连自己吗？      从 VPS 连自己的端口
5. 换个网络能连吗？          另一个运营商，或外部多点检测
6. 是 IP 被封还是域名问题？  直连 IP vs 域名
7. 传输层握手能完成吗？      TLS / WebSocket 握手
```

## 1–2. 服务和监听

```bash
systemctl is-active <服务>
systemctl status <服务> --no-pager -l | tail -20
ss -ltnp | grep <端口>
```

绑定在 `127.0.0.1` 的服务收不到外部连接。但**这可能是正确的**——反向代理后面的入口本来就只监听回环。所以先确认这里是否**应该**有代理在前面，再决定要不要改成 `0.0.0.0`。

## 3. 两层防火墙

两层都必须放开：

```bash
ufw status verbose
nft list ruleset | head -40
```

以及服务商控制台里的安全组。

**只开主机防火墙、服务商那层没开，会得到一台看起来完美但永远不回应的服务器。** 这是新部署"装死了"最常见的原因。

从外部实际测试，不要相信任何一边的配置：

```bash
nc -vz -w 5 <vps-ip> <端口>
```

## 4. 回环自测

端口本地通、外部不通 → 问题在防火墙或服务商，不在代理配置：

```bash
# 在 VPS 上
nc -vz -w 5 127.0.0.1 <端口>
```

## 5. 换一个网络

**一个网络不构成证据。** 单一运营商的超时，可能是那个运营商、那条路由，或者地址被封。

- 换网络试（手机热点、另一个运营商）；
- 用外部多点检测看是"到处都不通"还是"只有用户所在地区不通"；
- 对比**直连 IP** 和**域名**：IP 通但域名不通 → 查 DNS；两个都不通 → 查路径。

做完这一步，才能说"这个地址在该地区被封"，而不是"它不能用"。

## 6. 到底被封的是什么

区分下面几种情况，因为修法完全不同：

| 观察 | 可能在哪层 |
| --- | --- |
| 直连 IP 的 TCP 到处都连不上 | 端口被封，或服务/防火墙问题 |
| 只有一个地区 TCP 连不上 | 该地区对地址或路由做了过滤 |
| TCP 能连，TLS 握手卡住或重置 | 基于 SNI 的过滤，或证书/SNI 不匹配 |
| TCP+TLS 都正常，WebSocket 升级失败 | 反向代理的路径或头部配置错 |
| 全都连上，但没有流量通过 | 代理凭据、UUID 或路径不匹配 |

用 CDN 的域名去连源站 IP，如果报 `TLS alert internal error`，通常意味着源站期望流量是经过 CDN 到达的（或证书不覆盖那个名字）——**不代表源站挂了**。

## 7. 路径里有 CDN 时

如果客户端通过 CDN 到达 VPS，加这几项检查：

```bash
# 未知路径返回的是你的代理还是 404？
curl -sI https://<cdn域名>/does-not-exist

# 配置的路径和随机路径行为不同吗？
curl -sI https://<cdn域名>/<配置的ws路径>
```

预期：未知路径 `404`，配置的路径**不是** `404`（裸 `GET` 通常是 `400`，因为缺少升级头）。如果配置的路径也返回 `404`，说明反向代理没匹配上。

另外确认 CDN 的回源 TLS 模式。`Full` 会加密到源站但不校验源站证书；`Full (strict)` 会校验。改模式时要**限定到那一个域名**，不要动整个 zone。

## 最大的坑：把自己锁在外面

改动任何影响路由、防火墙、SSH 或"你自己正在用的那条代理链路"之前：

1. 确认有**第二条独立入口**（服务商控制台、串口控制台，或者已经开着的第二个 SSH 会话）；
2. 确认改动可回滚，并且你知道确切的恢复命令；
3. 如果你的 agent 会话是**通过**这个 VPS 连出去的，**停下来**，先让用户确认恢复访问的手段。

一个切断了自己连接的 agent，既完不成任务，也回滚不了。

## 反面做法

- **端口根本没开就去改代理配置。** 先查防火墙，这是免费的，而且通常就是答案。
- **用换协议来修端口被封。** 如果地址被过滤，同地址上的新协议可能同样被过滤。先测地址。
- **把"服务在跑"当成"服务可达"。** `active` 只说明进程没退出。
- **用一个网络判断可达性。** 单运营商超时几乎证明不了什么。
- **"测试一下"就关掉防火墙。** 开那个具体端口，不要为了省事把防护拆掉。

## 报告模板

```
服务=<active/inactive>  监听=<地址:端口 或 无>
主机防火墙=<端口放行? 是/否>
服务商防火墙=<已核实? 是/否/未知>
回环=<通/不通>
外部TCP=<通/不通>  来自=<网络>
其他网络=<结果>
直连IP=<通/不通>  域名=<通/不通>
TLS握手=<通/不通>  WS升级=<通/不通>
失败层=<服务 | 主机防火墙 | 服务商防火墙 | DNS | 路径过滤 | TLS/SNI | 代理配置>
恢复入口=<你还能怎么进去>
未验证=<测不到的部分>
```
