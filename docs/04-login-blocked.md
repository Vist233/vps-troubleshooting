# 4. 网站能开但登录失败

隧道通了，不等于账号能用。用风控和验证挑战保护自己的网站，会把 IP 当成一个信号，而 VPS 地址是它们不喜欢的信号。

这一页讲的是**怎么正确读证据**，不是怎么绕过防护。没有可靠的技术绕过手段，仓库也不应该假装有。

## 第一步：你实际观察到了什么

下面这些是完全不同的结果，不能合并：

| 观察 | 能证明什么 |
| --- | --- |
| 不带凭据请求 API 返回 `401` | 请求到达了 API。**不**代表账号能用 |
| 带有效凭据请求 API 返回 `200` | 该账号从该出口可以做这次调用 |
| 页面返回 `403` 并带挑战头 | 有风控在挑战客户端。不是网络故障 |
| 页面能开但登录表单反复失败 | 会话、Cookie 或挑战问题，通常是客户端侧 |
| CLI 工具报授权错误 | 账号权益或挑战问题，不一定是隧道 |

最常见的报告错误是：*"API 返回 401，所以 OpenAI 通过这个节点是通的。"* 并不通。`401` 是未认证请求的**预期**答案，它对真实登录能不能过什么都没说。

## 第二步：出口是不是问题

目标网站看到的是**出口**地址，也就是 VPS。在 VPS 前面加 CDN 改变的是**入口**，**不是出口**。

所以：

- 加 CDN **不**改变目标网站对地址的评分。
- 换传输方式（Shadowsocks → VLESS/WS）**也不**改变出口。
- 只有换出口地址，或者换账号/会话，才改变目标网站看到的东西。

按目标网站看到的样子核实出口：

```bash
# 走代理
curl -s https://api.ipify.org
```

和 VPS 自己的公网地址比对。如果一致，出口就是这台 VPS，加 CDN 没有改变这一点。

## 第三步：区分三类失败

| 类别 | 信号 | 现实可选项 |
| --- | --- | --- |
| **传输** | TCP/TLS 失败、超时、重置 | 修路径，见 [03-unreachable.md](03-unreachable.md) |
| **风控挑战** | `403` + 挑战头、验证码、无限跳转 | 换出口地址、换住宅/移动网络，或接受限制 |
| **账号/权益** | 认证通过但被拒、配额或地区提示 | 账号侧问题，换网络没用 |

第三方的"IP 纯净度"或风险分只是**第三方信号**。它不是目标网站的评分，一个"risk 66"不代表"66% 干净"或者"一定会被封"。不要把它当判决书。

## 第四步：可以诚实尝试的事

按顺序，并保持诚实的预期：

1. **用真实浏览器、在用户自己的设备上、登录状态下验证。** 大多数"被封了"的报告，其实是正常浏览器能通过的挑战。这是最便宜的测试，也最常直接结案。

2. **换一个出口试。** 另一台不同机房的 VPS，或者用户家里的网络。家里能通而 VPS 不通，出口就是变量。

3. **换个时段试。** 风控判断和挑战频率随时间变化。某一刻失败不是永久判决。

4. **接受边界。** 如果机房出口被持续挑战，而用户需要稳定访问，诚实的答案是：这个出口不适合那个服务。说出来，而不是继续往上堆代理层。

## 不要做的事

- **不要靠再套一层代理来"修"它。** 加跳数改变的是延迟，不是出口身份——除非最后一跳是另一种性质的地址。
- **不要把挑战说成封号。** `403` + 挑战意味着"证明你不是机器人"，不是"你的账号被终止了"。
- **不要把第三方评分当权威。** 当成多个信号之一引用，并注明来源。
- **不要用部分信号宣布成功。** 未认证 API 的 `401`，或者静态资源返回 `200`，都证明不了什么。
- **不要帮着绕过防护。** 解释这些信号的含义是正当诊断；构造挑战绕过不是。

## 报告模板

```
出口IP=<走代理观察到的>
出口是否等于VPS=<是/否>
API未认证=<状态码>          # 401 是预期的，只证明可达
API认证=<状态/结果>         # 需要用户的凭据
网站HTML=<状态码> <有无挑战头>
真实浏览器登录=<用户是否验证过：是/否/未尝试>
第三方风险=<来源> <数值>    # 只是信号，不是判决
类别=<传输 | 风控挑战 | 账号 | 未确定>
建议=<...>
未验证=<...>
```

最后一行永远要诚实。"隧道已验证，真实登录未验证"是一个完整且有用的结果。只测了隧道就说"能用了"不是。
