# 5. 多设备：一个订阅，几个客户端

把一个配置发给手机、笔记本、平板，听起来很简单，实际上是支持时间消耗最多的地方。故障通常不在代理，而在订阅、客户端或规则集体积。

## 只保留一个真相来源

一个文件，一个 URL，所有设备共用。除非真的存在不兼容，**不要**维护"手机版"和"电脑版"。

```
/srv/clash/<token>.yaml   ← 唯一的配置
        │
        ├── HTTPS (gzip)  → 设备 A
        ├── HTTPS (gzip)  → 设备 B
        └── HTTPS (gzip)  → 设备 C
```

好处：改节点只有一个地方，只有一个哈希要核对，不会漂移。某个设备加载不了，那是要诊断的客户端问题，不是分叉配置的理由。

## 规则集要小到能被加载

这是最容易被忽略的多设备问题。

从几个公开来源拼出来的规则集可以到约 12 万条、约 2.5 MB YAML。桌面端无所谓。手机上，如果客户端有内存上限，这是"节点列表空白"或"加载失败"的一个**可能**原因——**是可能，不是定论**。没有客户端侧证据就不要当成原因。

无论如何都可以做的：

- **用 gzip 提供。** 约 2.5 MB 的 YAML 压到约 560 KB。实测里这让拉取时间从约 180 秒降到约 42 秒。只影响下载，永远不影响代理吞吐。
- **优先用编译后的规则集。** Mihomo 的 MRS 是二进制规则集，大集合加载比等价 YAML 快得多。
- **合并没有理由存在的分组。** 如果 "Google"、"Gemini"、"Antigravity" 都指向同一个出口，它们就是一个组。组越少，新设备上出错的地方越少。
- **永远不要把 `REJECT` 放在服务选择组的第一位。** 没有选择缓存的新设备会继承第一项，静默断网非常难查。

## 客户端真正需要什么

最小可用的订阅：节点、少量选择组、规则。别的都不要。

会破坏可移植性、**不应该**写进共享订阅的：

| 不要包含 | 原因 |
| --- | --- |
| 绝对文件路径 | 只在写它的那台机器上有效 |
| 具体网卡名（`en0`、`eth0`） | 设备相关 |
| 写死的 CDN 边缘 IP | 会变；用域名 |
| `tun`、DNS、`hosts` 设置 | 各平台各客户端都不同 |
| 本地控制端口 | 会和客户端自己的冲突 |

共享文件保持可移植，让每台设备自己设 DNS/TUN。

## 诊断"订阅拉下来了但节点列表空白"

这是客户端侧症状，有几种可能。改服务器之前先区分：

1. **下载成功了吗？** 用客户端的 User-Agent、在普通网络下拉一次。如果完整返回 YAML，服务器没问题。
2. **是拉取失败还是解析失败？** 超时是网络；带解析报错的加载失败是内容或兼容性。
3. **客户端是不是自己叠了覆写？** 有些客户端会在订阅之上合并全局脚本或配置。那个覆写可能注入了服务器根本没发的字段——**要看客户端实际生效的配置，不是服务器上的文件**。
4. **规则集对这个客户端是不是太大了？** 用裁剪版测一次，看体积是不是变量。这是诊断手段，不是要发布的版本。
5. **同一台设备、同一个网络，换个客户端行不行？** 行 → 问题是那个特定客户端，不是订阅。

做完这些才能说故障在哪。

**不要**从一次失败就断定"客户端坏了"，也不要因为另一台设备拉取成功就断定"配置没问题"。桌面端能拉，不代表手机能加载。

## 选择组和预期管理

`select` 组是手动的，**不会自动故障切换**。

如果用户期待自动回退，需要 `url-test` 或 `fallback`——然后必须接受出口可能静默改变。说清楚这个订阅提供的是哪种行为。不要让人把手动组当成冗余。

还要明确：**几个组指向同一个节点不是冗余。** 只有一个出口时，每个组都解析到那个出口。

## 以后加第二个入口

当在直连入口之外增加一个 CDN 入口时：

- 新导入应该默认选**用户网络上实测更好**的那个——先测，不要假设；
- 已有设备可能保留上次的选择，要告诉用户手动切换；
- 旧入口保持可用，直到新入口在真实设备上验证通过。

## 报告模板

```
订阅URL=<脱敏>                 # token 是凭据
原始大小=<字节>  gzip后=<字节>
外部拉取=<状态码> <秒数>
SHA256=<哈希>                  # 你的完整性基准
节点数=<n>  组数=<n>  规则条目=<n>
设备A=<客户端+版本> <结果>
设备B=<客户端+版本> <结果>
失败层=<服务器 | 下载 | 客户端解析 | 客户端覆写 | 规则集体积 | 未确定>
可移植性排除=<你刻意没放进去的东西>
未验证=<没测的设备或网络>
```
